# readme-bot

A skill (and equivalent prompt) that reviews a replication package README against the [Template README](https://social-science-data-editors.github.io/template_README/template-README.html) of the Social Science Data Editors.

The Template is a suggestion, not a gate. The skill reports differences and, when it can see the replication package, drafts an improved copy.

## What it checks

- **Structure**: English sections that correspond to the Template, in a sensible order, with Template instructions removed.
- **Content**: each section contains what a replicator needs (data access, file list, software versions, seed, runtime, run order, table/figure map, references).
- **Style**: short, not chatty, no AI-speak, lists over prose and tables, instructions in chronological order.

## What it produces

- `README-review.md`: findings by section, tagged High / Medium / Low.
- `README-ai-edited.md` (only if the package is available): the original README restructured and filled with facts found in the package. Unverifiable items are marked `[AUTHOR TO VERIFY: …]` / `[AUTHOR TO PROVIDE: …]`. The original is never modified.

## Use it

- **Claude Code**: copy `skills/readme-review/` into `.claude/skills/` (project) or `~/.claude/skills/` (user). Then ask: "Review the README in this package."
- **claude.ai**: download `readme-review.zip` from the latest release (or run `scripts/build.sh`) and upload it under Settings → Capabilities → Skills.
- **Other chat tools**: paste [`prompts/readme-review-prompt.md`](prompts/readme-review-prompt.md), then attach the README and, if possible, the package or its file listing.

## Repository layout

- `skills/readme-review/`: the skill (source of truth).
  - `SKILL.md`: procedure.
  - `references/`: Template section checklist, style guide, package checks, report format.
  - `VERSION`, `FEEDBACK_URL`.
- `prompts/readme-review-prompt.md`: single-file prompt, generated by `scripts/build.sh`. Do not edit by hand.
- `feedback/`: [feedback plan](feedback/FEEDBACK_PLAN.md), survey spec (`survey-spec.json`) and [questions](feedback/questions.md) (generated from the spec; do not edit), Qualtrics field map, exported survey (`survey.qsf`, once created).
- `scripts/create_survey.py`: creates the survey in Qualtrics from the spec via the API.
- `scripts/build.sh`: builds the prompt and `dist/readme-review.zip`.
- `scripts/qualtrics_to_prs.py`: opens one PR per new survey response in the private feedback repository (run daily by a workflow there).

## Feedback and changes

Users give feedback through a Qualtrics survey linked at the end of each report. Each response becomes a pull request in a private repository (`readme-bot-feedback`); a maintainer includes it by approving the PR, or rejects it by closing it. Skill changes based on that feedback come in separate PRs. See [feedback/FEEDBACK_PLAN.md](feedback/FEEDBACK_PLAN.md).
