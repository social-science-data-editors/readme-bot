readme-bot

An AI skill that reviews the README of a replication package against the Template README, and tells you what a replicator would miss.

Skill v0.1.0 Works with Claude, ChatGPT, Gemini, Copilot, and others Source on GitHub · MIT license

What it is

readme-bot is a set of instructions for an AI assistant. You give the assistant your README, and optionally the replication package. It returns a list of differences from the Template README, ranked by how much they would slow a replicator down.

A · Structure

Are the Template's sections there, in a sensible order, with the Template's instructions and example text removed?

B · Content

Does each section say what a replicator needs: data access, file list, software versions, seed, runtime, run order, table and figure map, references?

C · Style

Is it short and plain? Lists over prose, steps in the order you run them, no filler, no AI-speak.

Who it is for

  • Authors, before submitting a replication package.
  • Data editors and journal staff, as a first pass before a human review.
  • Replicators, to see quickly what a README leaves out.

What it is not

  • Not a gate. The Template is a suggestion; the review says what differs and why it matters. It never says a README "fails".
  • Not a journal decision. Passing or failing a data editor's check is still up to the data editor.
  • Not a review of your research. It does not judge the paper, the methods, or the results, and it does not run your code.

Security and privacy

readme-bot is text: instructions an AI assistant follows. It sends nothing anywhere by itself. The questions below are the ones we expect, with straight answers.

Where do my files go? To the AI provider you choose. Nowhere else.

The skill has no code and makes no network calls. Whatever you give your AI assistant goes to that assistant's provider (Anthropic, OpenAI, Google, Microsoft, …) under your account's terms.

  • Review only: you share just the README.
  • Review + edited copy: you also share the package, or only its file listing. A listing (for example the output of find . -type f) is enough for most checks and contains no data.
My package has confidential or restricted data. Do not upload it.
  • Check your data use agreement and your institution's AI policy before giving any part of the package to an AI tool.
  • Safe default: give the README and a file listing, not the data.
  • If your institution has an enterprise or education AI account (often with no-training terms), use that rather than a personal account.
Will it run my code or change my files? It is told not to. Keep an eye on it anyway.
  • The skill tells the assistant not to run the replication code.
  • It never modifies your README. It writes two new files: README-review.md and, in edit mode, README-ai-edited.md.
  • Coding agents (Claude Code, Codex, Copilot agent mode, Cursor) can run commands on your machine. Keep their approval prompts on, and point them at a copy of the package.
What exactly am I installing? Five Markdown files and two one-line text files.

No scripts, no executables, no dependencies. Read them before you install:

  • SKILL.md: the procedure.
  • references/: Template checklist, style guide, package checks, report format.
  • VERSION and FEEDBACK_URL: the version number and the survey link.

The single-file prompt (readme-review-prompt.md) is the same text, concatenated.

Can it make things up? AI can. The skill is built to make that visible.
  • The edited copy fills gaps only with facts found in the package (file names, seeds, package lists).
  • Anything it cannot verify appears as [AUTHOR TO VERIFY: …] or [AUTHOR TO PROVIDE: …].
  • It is told never to invent data sources, versions, runtimes, URLs, DOIs, licenses, or hardware. It may still do so. Check every change before you use it.
  • If you find an invented fact, tell us in the survey. Our target is zero.
What happens to my survey answers? Anonymized, reviewed, private by default.
  • The survey runs on Cornell's Qualtrics with anonymized responses (no IP address or location stored).
  • Email is optional, only for a reply, and never leaves Qualtrics.
  • Each response becomes one pull request in a private GitHub repository. A maintainer includes it or rejects it.
  • We quote you in public (anonymized) only if you say yes.
  • Before a maintainer reads it, free text is checked automatically for links, code, and instructions aimed at an AI. Nobody, human or AI, applies your text to the skill directly: a maintainer writes any change.

Details: feedback plan.

How to use it

Pick the line that matches your tool. All three give the same review. Links always point to the current version.

Coding agent

Claude Code (or another agent that reads skills)

  1. Copy the folder skills/readme-review/ into .claude/skills/ in the package, or into ~/.claude/skills/ for all projects.
  2. Open the package folder.
  3. Ask: "Review the README in this package."
Chat with skills

claude.ai

  1. Download readme-review.zip (latest release).
  2. Settings → Capabilities → Skills → upload the zip.
  3. In a new chat, attach the README (and the package zip or a file listing). Ask for a review.
Any chatbot

ChatGPT, Gemini, Copilot, others

  1. Download readme-review-prompt.md.
  2. Paste it into the chat, or attach it.
  3. Attach the README, and if you can, the package or its file listing.

Tips

  • Say "review only" if you do not want an edited copy.
  • Large package or restricted data? Give a file listing instead of the files: find . -type f > files.txt (macOS, Linux) or dir /s /b > files.txt (Windows).
  • READMEs in PDF, Word, LaTeX, or plain text work. The edited copy is always Markdown.
  • Non-English README? It is reviewed anyway; the edited copy is in English.

What to expect

One report, always. An edited copy only when the assistant can see the package. A good README gets a short report.

Always

README-review.md

  • One-line verdict and counts by priority.
  • Findings by section: what is wrong, where, and the fix.
  • No praise, no padding.
  • Ends with the feedback link.
If the package is available

README-ai-edited.md

  • Your README, restructured into Template sections.
  • Your wording kept where it works.
  • Gaps filled only from the package; the rest marked AUTHOR TO.
  • Your original file is untouched.

Priorities

  • High: a replicator cannot proceed or cannot reproduce a result (no data access, no entry point, unmapped tables, missing software).
  • Medium: a replicator can proceed but will lose time or guess (no versions, no runtime, unclear order).
  • Low: style or polish.

A report looks like this

Illustrative excerpt, not a real review

# README review: README.pdf

- Skill: readme-review v0.1.0 · Template v1.2 · 2026-11-13
- Mode: edit (package available)
- Verdict: Close to Template; data access details and table map incomplete.
- Findings: 2 High · 3 Medium · 4 Low

## B. Content

### Data Availability and Provenance Statements
- **High** — The survey data has no access instructions. Fix: give the
  URL or contact, cost, and expected wait time.

### List of tables and programs
- **High** — Tables 4–6 are not mapped to a program. Fix: add rows for
  them (code found in programs/03_robustness.do).

## C. Style
- **Low** — Overview: "In this comprehensive replication package, we are
  delighted to provide…" → "This package contains the data and Stata
  code to produce all tables and figures."

What we most want to know

  1. Did the report flag something that is not a real problem? Which, and why?
  2. Did it miss a problem you know about?
  3. Did the edited copy contain invented facts: versions, URLs, data sources, runtimes?
  4. Which AI tool and model did you use, and how (chat, coding agent, API)?

Rules for answering

  • Answer yourself. Do not let an AI assistant fill in the survey.
  • An assistant may help with one question. If a review went wrong, ask your assistant why, and to propose concrete changes to the skill files. Read its answer, then paste it as plain text into the "Proposed changes" question and say who wrote it.
  • Leave out confidential data, unpublished results, and names.

What happens next

  1. Your response becomes a pull request in a private repository, within a day.
  2. A maintainer reads it, and includes or rejects it.
  3. Included responses shape the next skill version. The changelog cites them by ID.

Other ways to reach us

  • Bug in the skill or this page: open an issue.
  • Disagree with the Template itself: template_README issues.
